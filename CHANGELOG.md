# Changelog

## Unreleased

- **NP1: record is harder to fool.** Each sample run varies the page size and the heading text away from the old fixed samples (1920×1080, 1080×1920, 1080×1080, 320×200, 1200×800, 4K, and the old strings). The child moves `Date` and `performance.now` forward by 6 seconds after the module loads, waits a short real delay, and hides `process`, `Buffer`, `global`, the Node timers, `structuredClone`, `fetch` and the document-sandbox timers while the add-on code runs. code-scan flags a direct check of those globals, of `Date.now()` / `performance.now()`, or of a historical sample size. What remains: sizes stay in a range the layout can use, the clock jump is not six seconds of wall time, `globalThis` itself stays, and a check built from strings at runtime is not flagged.
- **NP2, NP3, NP5, NP10 (placement)** were fixed with NP12. A locked logo or footer is content. A long heading wraps before it is refused. Images stay at 48 px or are refused. A heading that is already placed is not moved. The dark capture now sets `sp-theme` to dark, so the dashboard label "Home, dark" is not a light panel.
- **NP4: listing copy.** Lit and JSX panels contribute each text run and each label, placeholder, and alt, so a picture is not only the add-on name. A sandbox feature counts only when `runtime.exposeApi` publishes it (or the file never calls `exposeApi`). "Keeps your notes" is used only when `clientStorage` stores notes. A token is "Remembers your sign-in".
- **NP6: late press errors.** Each press is watched for 5.5 seconds, so a 4 second error on the last button is that button's error. An error that arrives after the watch stays on the press that caused it. A status the panel shows is a failed status, not a script error.
- **NP7:** `proxy.addImage.call(proxy, blob)` is an `addImage` call. `exposeApi(new DocApi())` publishes the class's methods, and the sample run and the browser stand-in call prototype methods.
- **NP8:** versions reject leading zeros (`01.0.5`). `--set` and `--bump` together are an error. A downgrade is written and the result carries a warning.
- **NP9:** the README install line is `npx skills add ThisIsMrAli/addon-developer-assistant`. The deleted pre-merge branch is not described as the form that works today.
- **NP12: even heading gaps.** In real Express (1.0.6) the gap between "Beta title" and "Gamma" was about three times the Alpha–Beta gap, and the headings jumped up and down on each add. Express hands out a new object for a node each time, so `ours.has(item)` never matched and the snippet treated its own headings as obstacles at their old places. The snippet now keeps only node ids, finds the nodes in `page.children` on every call, and uses one gap per page measured from `boundsLocal`. The stand-in returns a new wrapper for every node, so `===`, Set and Map identity fail as they do in Express, and `record` has a landscape "Alpha, Beta title, Gamma, image" page that checks even gaps.
- NP10: a new heading goes after the last one in the same column, and nothing already placed moves (a heading the user moved stays put). Everything is laid out again only when the new item does not fit.
- NP2: only a full-page or near full-page node is background. A locked logo or footer is content, and headings go around it.
- NP3: a heading wider than its column wraps (`TextLayout.autoHeight`) before it shrinks, then shrinks to 24 px before another column opens, and to 18 px as the last step.
- NP5: images are at least 48 px on the short side. One that cannot be (1x1000, 3000x10) is refused with "This image is too thin…".
- **NP11: the snippet no longer calls `Array.prototype.at`.** Heading Image 1.0.5 showed "not a function" on every Add heading and Add image in real Express: `planHeadings()` called `slots.at(-1)`, and the document sandbox's QuickJS has no `.at`. The throw also skipped `headings.pop()`, so every later layout threw too. The snippet now reads `slots[slots.length - 1]`.
- `record` runs sandbox code the way Express does. The sample-page child removes the built-ins QuickJS added in or after its 2023-12-09 release (`at`, `findLast`, `findLastIndex`, `toSorted`, `toReversed`, `toSpliced`, `with`, `Object.hasOwn`, `Object.groupBy`, `Promise.withResolvers` and the rest), and `structuredClone`, the timers, `fetch`, `WeakRef` and `FinalizationRegistry` are undefined. `editor` and `constants` exist only when imported. Code-scan names each use in a sandbox file, with the reason and a fix, in the source and in a minified build. The browser stand-in reports the same lines to the audit.
- The document stand-in exposes only the documented API (`references/sandbox-apis.md` lists each call and its reference URL). Any other member is undefined, so a call throws "not a function" as in Express: no permissive `editor.*` or `constants.*` fallbacks, no `ResizeBehavior.fill`, no `rescaleProportionalToWidth`, no settable `fontSize`, no `ItemList.forEach/map/filter`. Node types use the documented `SceneNodeType` values. `editor.queueAsyncEdit()` was removed from the SDK (Adobe changelog 2026-08-03), so it is no longer an accepted form and `record` says so.

## 0.5.1

- Placement is measured, not pattern-matched. `record` runs the sandbox code in a child Node process against a document stand-in on sample pages (landscape, portrait, square, a locked and an unlocked full-page background, thirty headings, a small page) and checks where every node lands: inside the page and clear of its edge, clear of other added nodes and of existing content, text at 18px or more, images at their bitmap's aspect ratio, one shared column while there is room, and columns that read left to right in the order added. Wrong maths fails whatever it is named, and equivalent maths with other names or argument order passes.
- The handoff snippet keeps the bitmap's aspect ratio in `initialSize` (Express rejects one more than 1% off), ignores a locked or full-page background, and fills columns left to right. The stand-in, used by `record` and in the browser audit, throws Express's aspect-ratio error. The stand-in runs the add-on's real sandbox code in the browser and returns its real value, so a status no longer reads "[object Object]".
- The audit reads panel status through shadow roots and watches each press for three seconds, so a late error, "is not a function", "Cannot read properties", or "Heading failed" is a failed press.
- The panel's sandbox calls are found through aliases, destructuring, and any field name. `runtime.exposeApi` is read through alias chains, spread, assigned properties, `Object.assign`, and wrapper objects. An afterAsyncCallback passed by name counts.
- Listing copy says what the code does. Listing pictures are real captures of the built panel; without Chrome the step fails with the reason. Each text slot gets a different phrase.
- `develop.mjs version --set X.Y.Z | --bump patch|minor|major`. `dashboard.mjs stop` without `--out` stops the dashboards the review and develop sessions point at. The dashboard's step counts use one list. The README install line works before the merge (`#branch`).

## 0.5.0

- A throw is covered when a wrapper (`_run`, `_guard`, `_act`) calls it inside `try`, including a throw two calls deep, a class method, a `.then().catch()` chain, a function passed by reference (`array.map(fn)` inside `try`, or `fn.bind(this)`), and an alias of that function. A throw nothing calls, and a throw with no `try` on its path, still fail `record`. The stand-in answers only the methods passed to `runtime.exposeApi`. A panel call to a method the sandbox does not expose fails `record`. `createImageContainer()` has to run in the afterAsyncCallback of `editor.keepContentActiveDuringAsync()` (Editor reference, Example 2) or in `editor.queueAsyncEdit()`. A `_sandboxProxy` call is a sandbox call, not `addOnUISdk.app.document.addImage`. Headings share one centre line. The next heading stacks under the previous one, and a second column is used only when that line cannot take another heading at a readable size. The image sits below that column and moves down when the column grows. Listing copy is written from the feature, not copied from the brief, and the stage is a picture of the panel. Feasibility evidence is a sentence. The refusing sudo stays on `PATH` until the dev server process exits, including after the CLI itself has exited. The audit fills text fields before it presses a button, writes those presses to `audit.json`, and treats an error the panel catches and shows as status text as a script error.
- A throw is covered when a wrapper (`_run`, `_guard`, `_act`) calls it inside `try`, including a throw two calls deep and a class method. A throw nothing calls, and a throw with no `try` on its path, still fail `record`. The stand-in exposes the sandbox methods the add-on actually calls, returns a real PNG from `createRenditions`, and the audit presses the primary buttons. Console lines for an uncaught exception or an unhandled rejection count as a script error. A docs step that says "0 failed" stays green. Listing copy uses the brief when the panel has no other phrase, and the stage keeps a local panel image. Headings and images share one free-space layout: the first item stays centered, the next goes below existing `boundsInParent`, and a full page wraps to the next column or shrinks instead of stacking. Template `Get Started` titles and the split keywords meta are replaced, and a newly created CA does not say it was reused. Chrome's temp files stay inside the profile directory. The refusing sudo stays on `PATH` until the dev server exits.

- **The generated add-on is audited by Add-on Preflight.** The browser run rewrites the Adobe SDK import to a stand-in labelled `express-sdk-stand-in`. That run sets `expressPass` to false.
- **BETA: real Express is its own step, immediately before the listing.** It is optional. The question is "Run a real test in Adobe Express (beta)?" Skip is the default and the recommended option, and the next question is the listing and the screenshots. Run trusts the dev CA (apt, then the Debian pool), serves `https://localhost:5241`, and opens a visible browser for the person to sign in. Chrome flags are not disabled, `--ignore-certificate-errors` is not used, and the host is never `127.0.0.1`.
- `npm run test:box` runs the suite without the browser walk and without the live scaffold. It does not start Chrome or Edge unless `BOX_TEST_BROWSER=1`. A listing fit whose Chrome does not finish fails in seconds instead of waiting a minute.
- GitHub Pages deploys only when the owner starts the workflow by hand.
- Re-running `begin` keeps the add-on and the answers. `--empty` is refused on a folder that already has files. A doc fetch that never returns ends with the budget, and a failed page is a label, not a step status. Every command prints a next line. Approval cards use plain words, one recommended choice, and no document hash. `npx skills add` installs both skills into the same parent. A Lit or JSX panel is judged from the script and the bundle, not only from `index.html`. Loading placeholder text is not a listing summary. A fresh home gets the localhost certificate `@adobe/ccweb-add-on-devcert` looks up, signed by the home CA, with no sudo. Heading text is capped and fitted to both the width and the height. A later heading is placed below existing content or the selection so two headings do not overlap, and it stays inside the page. `clientStorage` is the binding, not the parameter name. Skip reasons are separate sentences. A failed record says to run record again. Feasibility evidence is plain text. Temp profiles and sudo shims are removed. The private install path is the local checkout, or the remote name after GitHub authentication.

## 0.4.0

- **The agent no longer stops while it waits.** A chat that ended its turn after you pasted a license code in the dashboard was the bug. Now the first rule in `SKILL.md` is to keep going until `session.mjs done`, every command ends with a `next` line that says what to run, `session.mjs next` answers "what now?" at any point, and the dashboard shows an "agent quiet" banner with a one-click "Copy continue" if a chat ever does go quiet.
- **A real UI check.** `audit.mjs` opens the panel in headless Chrome at 320px, in light and dark, with reduced motion, and clicks through it like a person (never Delete, Reset, Buy, or Sign out). It finds what the code scan cannot: a dialog whose close button sits at the bottom, a dialog with no way out, a control covered by another, text clipped or overflowing, broken images, unreadable contrast, controls a keyboard cannot reach, and script or network errors. Each finding has an annotated screenshot and a guess at the source line.
- **Confirmed UI bugs are fixed first, without a question.** Warnings go into the one "fix everything" question. The audit runs again afterwards and marks what is really gone.
- **An optional polish step, only on approval.** `references/polish.md` is a short, measured set of spacing, type, and state rules, so the panel looks finished without being redesigned.
- **Paid screens without the secret passing through the agent.** A license typed in the dashboard stays in the dashboard's memory for that review. `audit.mjs --licensed` fetches it from the loopback server with the token, uses it, and never writes it down.
- **A new dashboard.** A "Now" card with a live timer and a progress bar, an agent pill that says whether the agent is working, waiting for you, or quiet, steps with a reason and a duration, findings by severity with screenshots, and the decisions as buttons. Status never relies on color alone. Light and dark, reduced motion respected, system fonts only.
- **No Adobe login to walk the panel.** When nothing runs at the panel's address, the audit builds the add-on and serves the build from this computer, rebuilding when a source file the build reads has changed since. It steps through a welcome tour, then explores the screens behind it.
- **Fewer false alarms, more real ones.** A sheet or scrim laid over many controls on purpose, a menu that is open, and a control scrolled out of view are not bugs. Something you cannot see (opacity 0) that takes the clicks meant for the controls under it is, and it is reported as `invisible-cover`. A source line is named only when one place holds the label or the rest of the screen settles it.
- **A walk that says where it is.** While light finds screens it counts them ("5 screens found so far") and the dark replay shows "3 of 12". Each screen is named in the activity feed. A walk that stops early says whether the time or the screen limit ended it. A second audit in the same review is refused while the first runs.
- **No stale waiting line.** Once your answer is read, the step shows "You chose …" instead of "Waiting for your answer". The agent is told to report each file it edits during the fix and polish steps, so the page keeps moving.
- Tests cover the audit against fixture panels in real Chrome, including the close-at-bottom dialog, a refused and an accepted license, a re-run that confirms a fix, and the dashboard's wait, answer, and secret paths.

## 0.3.0

- A live dashboard in Chrome, offered once at the start, with chat as the fallback. Every approval is a click there. It listens on this computer only, behind a token, and Adobe's reviewers never see it.
- The scanner reads code the way a person does. Comments are ignored, markup is read tag by tag (multi-line JSX, spread props, Spectrum and React Spectrum controls), and a rule that needs a project-wide answer, such as Cancel, logout, or validation, looks at the whole project.
- Upload package check. A zip in the project root is read in memory and checked for the manifest at its root, the 50 MB limit, hidden files, the files the manifest names, and whether it is older than the source. `--zip` checks one stored elsewhere.
- A rejection letter workflow. Each reason becomes a tracked note, is mapped to a check, and is verified by itself. The skill ends with the notes to paste into the resubmission.
- New checks drawn from Adobe's list of common rejections: no way back out of a screen, an honest Cancel, credits and test credentials for the reviewer, and the panel on a slow or offline network.
- Listing screenshots render with one command, `render-listing.mjs`, on macOS, Windows, and Linux. It refuses a page that left the locked template and flags any phrase that is not in the add-on's source.
- CI runs the tests on Node 18, 20, and 22, on macOS, Windows, and Linux.
